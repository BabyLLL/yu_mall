# Spec Delta

## Purpose

定义摊位订单在后端的完整生命周期：摊位下单接口（仅商品+数量+备注）、按天流水取货码的生成规则、摊位订单状态机的状态与合法流转、以及未付款订单的超时自动取消。这是顾客端与摊主端共同依赖的订单行为契约。

## ADDED Requirements

### Requirement: 摊位下单接口

系统 SHALL 提供摊位下单接口，入参仅包含商品与数量列表和备注，SHALL NOT 要求收货地址、优惠券、积分或支付方式。接口 SHALL 校验商品上架状态与库存，按商品现价计算应付金额（无运费、无折扣），并锁定库存。原有电商 generateOrder 接口 SHALL 保留但不再是小程序的使用路径。

#### Scenario: 使用摊位接口下单

- **WHEN** 已登录会员调用摊位下单接口，传入合法的商品数量清单与备注
- **THEN** 创建订单：总金额=应付金额=商品现价合计，无运费/优惠/积分项，收货人信息为空，订单备注写入 note

#### Scenario: 下单时商品已下架

- **WHEN** 清单中某商品已被摊主隐藏（publish_status=0）或已删除
- **THEN** 下单失败并提示该商品已下架

#### Scenario: 下单时库存不足

- **WHEN** 清单中某商品库存小于请求数量
- **THEN** 下单失败并提示库存不足，已锁定库存不残留

### Requirement: 取货码生成规则

系统 SHALL 在订单创建时生成取货码：格式为 N + 三位以上按天流水号（N001、N002……），流水号每天从 001 重新开始，跨天不连续。取货码 SHALL 保存于订单上（pickup_code）并在订单查询中可获取。

#### Scenario: 每日重置

- **WHEN** 昨日最后一张取货码为 N042，今天第一张订单创建
- **THEN** 新订单取货码为 N001

#### Scenario: 并发下单号码唯一

- **WHEN** 同一天内多笔订单近乎同时创建
- **THEN** 每笔订单获得互不重复的递增取货码

### Requirement: 摊位订单状态机

摊位订单 SHALL 遵循状态机：已下单(待付款) → 已付款 → 制作中 → 待取货 → 已完成；"已下单"状态可被顾客或超时任务取消为"已取消"；已付款/制作中/待取货状态的订单仅摊主可取消。系统 SHALL 将原电商订单状态字段语义重映射为摊位状态（复用 status 数值段，映射关系在设计中明确）。

#### Scenario: 完整正常流转

- **WHEN** 订单依次经历摊主确认收款、开始制作、出餐完成、顾客取货确认
- **THEN** 状态依次变为已付款、制作中、待取货、已完成，时间戳分别记录

#### Scenario: 未付款超时自动取消

- **WHEN** 订单停留在"已下单"状态超过配置的超时时间
- **THEN** 订单自动变为已取消，释放锁定的库存

#### Scenario: 摊主取消进行中订单

- **WHEN** 摊主对已付款或制作中的订单执行取消
- **THEN** 订单变为已取消并退款处理标记由摊主线下完成，库存释放
